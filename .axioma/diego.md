## 🧠 LEARNINGS
## 2026-08-08 - Soporte Unificado para Presets de Períodos "Ayer" y "Últimos 90 días" en Reportes Cronológicos
**Learning:** El desacoplamiento limpio del backend de Business Intelligence (que acepta de manera generalizada objetos Date y retornos específicos de agregación) permite extender toda la experiencia de usuario y las opciones cronológicas únicamente del lado del cliente. Esto evita alterar schemas, consultas de base de datos o lógica de negocio redundante, garantizando una consistencia visual perfecta en el 100% de los reportes.
**Action:** Al diseñar presets de filtrado temporal, estructurarlos de forma modular y descriptiva del lado de la UI para reutilizar las capacidades analíticas existentes en el backend.

## 2026-08-07 - Cobertura de Pruebas Unitarias Robustas para Servicios de Reportes Analíticos (Compras, Taller, Clientes y Servicios)
**Learning:** Las llamadas asíncronas concurrentes (mediante `Promise.all`) que realizan consultas a la base de datos de manera paralela resuelven sus promesas en un orden determinado en JavaScript. Para simular con precisión las interacciones con la base de datos usando stubs de consultas secuenciales (como `db.select().mockReturnValueOnce()`), los valores simulados deben alinearse estrictamente con el orden en que se inician dichas llamadas asíncronas dentro de los servicios.
**Action:** Al simular flujos de consultas complejas concurrentes en servicios analíticos de Business Intelligence, rastrear siempre con cuidado el orden de invocación de las llamadas en paralelo dentro del hilo de JavaScript para estructurar de manera fidedigna la secuencia de los mocks.

## 2026-08-06 - Cobertura de Pruebas Unitarias Robustas para el Servicio de Reportes de Ventas
**Learning:** El testeo unitario de reportes de ventas que agrupan métricas por hora, día o mes requiere una configuración precisa de las fechas para alinearse con los desplazamientos de zona horaria local (`America/Argentina/Buenos_Aires`). El uso de un Proxy para simular las llamadas encadenadas de Drizzle ORM permite emular bases de datos en memoria complejas de manera predecible, validando promedios de tickets y cambios interperíodo sin dependencias externas.
**Action:** Continuar utilizando Proxy mocks encadenados para probar servicios con queries complejas de Drizzle ORM y validar siempre la precisión de cálculos contra valores nulos o vacíos.

## 2026-08-05 - Estandarización de Comparativo y Visualización de Margen de Rentabilidad
**Learning:** En el análisis financiero y de Business Intelligence, comparar porcentajes (márgenes) utilizando cambios porcentuales relativos puede resultar confuso y matemáticamente erróneo. Lo correcto para comparar variaciones entre dos márgenes es calcular y reportar la diferencia absoluta en puntos porcentuales (`p.p.`).
**Action:** Al implementar tendencias o comparativos temporales de indicadores de porcentaje (márgenes, tasas de conversión, etc.), calcular siempre la diferencia aritmética y utilizar el sufijo de puntos porcentuales (`p.p.`) para su visualización.

## 2026-08-04 - Cobertura de Pruebas Unitarias Robustas para el Servicio de Reportes de Rentabilidad
**Learning:** El testeo unitario de reportes que agrupan y ordenan datos por intervalos temporales (groupBy por hora, día o mes) debe consider con precisión los desplazamientos de husos horarios (Timezones). Como el servidor local calcula y asigna claves de buckets basándose en la zona horaria argentina (`America/Argentina/Buenos_Aires` o UTC-3), las fechas provistas en formato UTC puro deben desfasarse exactamente 3 horas hacia adelante (p. ej., usar `T03:00:00Z` en lugar de `T00:00:00Z`) para que caigan exactamente al inicio del día en la representation argentina y evitar desplazamientos de buckets que alteren el número esperado de elementos resultantes.
**Action:** Al modelar pruebas unitarias con librerías e internacionalización horaria local en el codebase de reportes, alinear siempre la entrada de fechas con la compensación de zona horaria del servidor.

## 2026-08-03 - Vista de Impresión de Alta Fidelidad y Accesibilidad WCAG AA en Reporte de Resumen (Overview)
**Learning:** Completar la acción de impresión en la página principal consolidada (Overview) cierra con broche de oro la suite analítica de informes de RPM Accesorios. El uso de estilos `@media print` dedicados junto con la estructura de tabla comparativa interperíodo permite generar PDFs ejecutivos de alto impacto para gerencia y auditoría. Al testear componentes con duplicados en pantalla y en la sección oculta de impresión, es mandatorio utilizar consultas de Testing Library como `getAllByText` para evitar excepciones de elementos duplicados.
**Action:** Mantener siempre el estándar de alta fidelidad con KPIs limpios, desgloses estructurados, y bloques de firmas de control en todas las plantillas corporativas de impresión.

## 2026-08-01 - Vista de Impresión de Alta Fidelidad y Accesibilidad WCAG AA en Reportes de Clientes y Stock
**Learning:** Completar la suite de reportes de administración con plantillas de impresión nativas de alta fidelidad garantiza una auditoría física impecable para gerencia. El uso de `@media print` permite ocultar dinámicamente elementos interactivos que no tienen sentido en papel (asistente virtual, selectores, botones y barra de navegación) y centrar la atención en KPIs limpios, desgloses estructurados y firmas de supervisor. Además, al duplicar elementos visuales entre la pantalla interactiva y el documento de impresión, las consultas de Testing Library deben reestructurarse usando `getAllByText` para evitar excepciones de elementos duplicados.
**Action:** Diseñar siempre esquemas de impresión estructurados con la identidad corporativa de RPM Accesorios, desgloses tabulares de KPIs, firmas de auditoría y controles de visibilidad limpios en todas las vistas de reporting.
